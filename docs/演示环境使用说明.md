### 2.2 患者管理端登录（需要图形验证码）


## 四、启动 / 停止 / 重启

```bash
cd packages/backend

# 启动（首次需构建镜像）
docker compose -f docker-compose.demo.yml up -d --no-build --pull never

# 重启单个服务
docker compose -f docker-compose.demo.yml restart caring-gateway-server

# 重建镜像（注意：沙箱内需指定独立 BUILDX_CONFIG）
export BUILDX_CONFIG="$HOME/.workbuddy/.docker-buildx-demo"
docker build --platform linux/amd64 -t caring-oauth-server:local \
  --build-arg JAR_FILE=target/caring-ucenter-server.jar \
  caring-ucenter/caring-ucenter-server

# 停止（保留数据卷）
docker compose -f docker-compose.demo.yml stop

# 完全销毁（含数据库卷，下次启动会重新初始化并丢失种子数据）
docker compose -f docker-compose.demo.yml down -v
```

## 五、演示环境 vs 原始 compose 的差异

`docker-compose.demo.yml` 相对 `docker-compose.yml` 做了以下调整：

1. **容器名加 `demo-` 前缀** — 不干扰宿主机已有的 `caring-*` 容器
2. **端口偏移** — 避开已占用端口
3. **移除 `build:` 段** — 避免 compose 触发 buildx（沙箱内受限）；镜像需手动构建
4. **移除 `platform: linux/amd64` 之外的 arm64 兼容处理** — 保留 amd64 以支持 Nacos 1.4.1
5. **tenant 服务使用 `Dockerfile.compose`** — 原始 Dockerfile 依赖不存在的 `SaasApp.zip`

## 六、已修复的代码缺陷

本次为跑通演示，修复了以下真实缺陷（均已验证生效）：

| # | 文件 | 问题 | 修复 |
|---|---|---|---|
| 1 | `caring-public/caring-common/.../LoginDecryption.java` | `loginDecryption()` 对明文手机号抛 `IllegalArgumentException`，患者端无法登录（前端传明文） | 解密失败时回退原值 |
| 2 | `caring-file/caring-file-biz/.../ScreenshotTaskServiceImpl.java` | 无条件 `@Autowired` `CaringMpcClient`，但该 bean 仅在 `caring.file.type=HW` 时创建 → LOCAL 模式下服务无法启动 | 改为 `required=false` + 空值保护 |
| 3 | `caring-msgs/caring-msgs-biz/.../OpenAiConfiguration.java` | `getOpenAiToken().get(0)` 未配置时 NPE → msgs 服务无法启动 | 降级为占位 token |
| 4 | `caring-nursing/caring-nursing-server/src/main/resources/bootstrap.yml` | Nacos 的 group/username/password 误绑到 `${NACOS_ID:...}`（命名空间 ID） | 改为 `NACOS_GROUP` / `NACOS_USERNAME` / `NACOS_PASSWORD` |
| 5 | `caring-cms/caring-cms-server/src/main/resources/bootstrap.yml` | 同上（username/password） | 同上 |
| 6 | `config-example/nacos/clientConfig/caring-gateway-server.yml` | 网关缺 `/ucenter/**`、`/nursing/**`、`/cms/**` 路由；oauth 路由指向不存在的 `caring-oauth-server`（实际注册名 `caring-ucenter-server`）；`/oauth/**` 与 `/ucenter/**` 写在同一路由（多 Path 谓词是 AND 关系） | 补全路由并拆分 |
| 7 | `config/sql/nacos-init.sql` | `tenant_info` 用 `UUID()` 随机生成命名空间，与 `config-dev.properties` 硬编码值不匹配 → 所有服务读不到 Nacos 配置 | 固化为 `c5bec804-e4c4-11f1-a4ec-0242ac150002` |
| 8 | `config/sql/nacos-init.sql` | `common.yml` 缺 `caring.application.encryption-key` → 手机号 AES 加密密钥为 null | 补充 `encryption-key` 与 `open-ai-token` |
| 9 | `config/sql/nacos-init.sql` | `redis.yml` 的 `provider_class` 为 j2cache 1.x 的类名，j2cache 2.8.2 的 `loadProviderInstance` 只认简写名 → NPE | 改为 `provider_class: lettuce` |

## 七、演示边界（需知悉）

1. **微信授权链路无法演示** — 患者端/咨询端的 `wx/login`、`guest/login` 需真实微信 appId + code
2. **患者管理端前端是桩代码** — `src/api/user.ts` 的 `userApiUrl.sava = '/'`，无真实业务 API；但后端登录链路已通
3. **AI 功能不可用** — 未配置真实 OpenAI token，`OpenAiService` 使用占位 token
4. **短信验证码未接** — `demo_*` 账号密码登录可用；短信通道需配置短信服务商
5. **x86 模拟导致启动慢** — 服务在 Apple Silicon 上通过 amd64 模拟运行，单服务启动约 3–6 分钟
