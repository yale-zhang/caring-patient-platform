### 三、修复的 9 个真实代码缺陷（详见演示说明第六节）

1. `LoginDecryption.loginDecryption()` 对明文手机号抛异常 → 加回退（患者端登录依赖）
2. `ScreenshotTaskServiceImpl` 无条件注入仅 HW 模式存在的 `CaringMpcClient` → `required=false`
3. `OpenAiConfiguration.getOpenAiToken().get(0)` NPE → 占位 token
4. nursing `bootstrap.yml` 的 Nacos group/username/password 误绑 `${NACOS_ID:...}`
5. cms `bootstrap.yml` 同上（username/password）
6. 网关缺 `/ucenter/**`、`/nursing/**`、`/cms/**` 路由；oauth 路由指向错误服务名；
   **`/oauth/**` 与 `/ucenter/**` 写在同一路由是多 Path AND 关系，必须拆开**
7. `nacos-init.sql` 的 `tenant_info` 用 `UUID()` 随机生成命名空间 → 与 properties 不匹配，固化为 `c5bec804-e4c4-11f1-a4ec-0242ac150002`
8. `common.yml` 缺 `caring.application.encryption-key` → 手机号 AES 密钥为 null
9. `redis.yml` 的 `provider_class` 为 j2cache 1.x 类名 → 2.8.2 只认简写名，改 `provider_class: lettuce`

### 四、关键技术要点

- **手机号 AES 存储**：`EncryptionUtil.encrypt()`，密钥 `sva4yAdvVa6I6Eyo`（AES/ECB）
- **前端手机号加密** `caringDecode()` = `base64('A' + base64('caring_' + phone) + 'B')`
- **后端解密** `loginDecryption()` = base64decode → 掐首尾 → base64decode → substring(7)
- **网关 header**：前端用 `token: Bearer xxx`（不是 Authorization）+ `tenant: base64('0000')`
- **分页参数**：`{"model": {...}, "current": 1, "size": 10}`
- **Nacos 配置更新必须走 API**（`POST /nacos/v1/cs/configs`），直接 SQL UPDATE 不刷新服务端内存，客户端读不到
- **Nacos 发布必须用真实换行**，写成字面 `\n` 会导致整份配置变成一行、YAML 解析失败

### 五、踩坑记录

- **沙箱 profile 超限**：WorkBuddy 生成 macOS sandbox profile 67614 字节 > 65535 上限，Bash 全面不可用。
  根因是 `~/.workbuddy/settings.json` 的 108 条 file preset 规则 + 13 条 extraAllowWrite。
- **buildx 沙箱拦截**：报 `failed to update builder last activity time ... operation not permitted`。
  解法：`export BUILDX_CONFIG="$HOME/.workbuddy/.docker-buildx-demo"` 换独立配置目录
- **Nacos 1.4.1 在 arm64 原生下会卡死在类加载**（`ZipInflaterInputStream.read`），必须用 `platform: linux/amd64`
- **`.gitignore` 的 `lib/` 规则**会隐藏 `node_modules/vue-demi/lib/`，误判"文件丢失"
- **x86 模拟下服务启动极慢**：单个服务 3–6 分钟，Nacos 首次启动约 9.4 分钟
